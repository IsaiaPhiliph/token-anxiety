# Token Anxiety

A macOS menu bar app (AppKit + SwiftUI, macOS 26+, Swift 6 language mode) that shows the five-hour and weekly usage of the user's AI plans. The user speaks Spanish (talk to them in Spanish), but the project is in English: code, UI texts, README, docs and commit messages. The app is localized: the English texts in the code are the keys, `Resources/es.lproj/Localizable.strings` is the Spanish translation (every new or changed text goes there too; `scripts/check-strings.py` fails while one is missing), and `Fmt.locale` follows the chosen language with the Mac's region. The code lives in the GitHub repo `IsaiaPhiliph/token-anxiety`, MIT licensed.

## Layout

- `Sources/TokenAnxietyCore`: everything testable without a window.
  - `Providers/`: one actor per service, conforming to `UsageProvider` (`isInstalled()`, `fetch() -> ProviderSnapshot`). Each has static parsers (`snapshot(...)`) that the tests feed with sample JSON.
  - `Models.swift`: `ProviderSnapshot` (`primary` is the five-hour figure, `secondary` the week), `UsageWindow`, `ProviderError` (Spanish messages; `needsUser` errors are not auto-retried).
  - `Achievements/`: `AchievementCatalog` (ids, tiers, texts), `AchievementFacts.compute` (what the ledger, the quota watcher and the app's counters add up to), `QuotaWatcher` (moments in the limits' cycles: 100 %, a reset at 95 %+, a week ended at 90 %+…) and `AchievementBook` (earned tiers with dates, never taken back; the first evaluation is announced as one summary). The app's `AchievementStore` keeps it in `achievements.json` and judges after each ledger update and snapshot.
  - `Pace.swift`, `History.swift` (`HistoryLog`, `AlertTracker`), `Formatting.swift` (`Fmt`, Spanish formats), `Demo.swift` (`--demo` data).
  - `Usage/`: the local usage history. `LedgerIndexer` reads Claude Code's and Codex's logs (`ClaudeLogReader`, `CodexLogReader`) into a `UsageLedger` (hourly buckets by provider, project, model, price tier and effort, plus `SessionSummary`s), saved in `~/Library/Application Support/TokenAnxiety/usage/usage.json` together with each file's checkpoint and the keys of the responses counted. `Pricing` (API prices, checked by hand: `Pricing.checked`), `ModelNames`, `ProjectNames` (cwd → repository, worktrees folded). `ContentReader` measures the sizes of prompts, tool results (filed under the tool that made the call) and replies in a second pass with its own checkpoint (`contentOffset`), so turning it on later still measures the logs on disk; `ContextGauge` is the live sessions' context over the model's window.
  - `Advice/AdviceRequest.swift`: the AI advice request (raw HTTP to the Messages API: `claude-opus-5-5`, structured output, `fallbacks: "default"` with `server-side-fallback-2026-07-01`). Only aggregates go; `TA_ADVICE_URL` points it at a local fake for testing, and the tests stub `URLProtocol`.
- `Sources/TokenAnxiety`: the app. `UsageStore` polls the providers, `StatusItemController` + `MenuBarRenderer` draw the status item, `PanelController` hosts `PanelView` in a borderless `NSGlassEffectView` panel, `Views/SettingsView` is the settings window. `Stats/` is the Statistics window: `UsageLedgerStore` (updates the ledger after each refresh), `StatsWindowController`, `StatsView` (sidebar of `StatsSection`s, period / service / cost toolbar, a `StatsScope` handed to each section) and one view per section; `MatrixHeatmap` and `ActivityHeatmap` are drawn by hand because Swift Charts lays out category grids poorly. Queries the window needs live in `Usage/UsageQueries.swift`, with tests.
- `scripts/build-app.sh` assembles and ad-hoc signs `build/Token Anxiety.app` (`--open [args]`, `--install`, `CONFIG=debug`). `scripts/make-icon.swift` draws the icon. `scripts/backdrop.swift` puts a plain gradient behind the panel for screenshots. `scripts/check-strings.py` checks a translation against the texts in the code.

## Commands

- `swift build`, `swift test` (Swift Testing, runs in milliseconds).
- `CONFIG=debug scripts/build-app.sh --open --demo --open-panel` to look at the UI with sample data; `--open-stats [overview|days|hours|projects|models|sessions]` opens the Statistics window (the demo has four months of made-up usage, `Demo.ledger`).
- `"build/Token Anxiety.app/Contents/MacOS/TokenAnxiety" --print --debug`: fetches every provider once against the real services and prints figures and steps (`--only antigravity,cursor` limits it; leave Claude out when repeating, it answers 429 to bursts). Never log tokens, emails or other secrets in `Log.debug`.
- `--print --advice [--send]` prints the exact AI advice request (and sends it, with the Keychain key or `ANTHROPIC_API_KEY`). `--export-card FILE.png [--achievements]` (no `--print`: it needs the app's run loop) writes a share card and quits.
- `--print --stats [--days N] [--store DIR]` reads the local logs instead (in memory unless `--store`) and prints tokens and ≈ cost per day, project and model. Check changes to the log readers against an independent tally of the same files (per day: requests, input, output, cache write, cache read).

## Data sources and pitfalls

- **Claude**: Keychain item `Claude Code-credentials` (JSON, `claudeAiOauth`) read with `/usr/bin/security`, which the item trusts (no prompt). `GET https://api.anthropic.com/api/oauth/usage` with `anthropic-beta: oauth-2025-04-20`. Access tokens last 8 h. Renewal (the user consented; setting `renewClaudeSession`): refresh grant with Claude Code's client id at `console.anthropic.com` / `platform.claude.com`, then write back the whole JSON with `security -i` on stdin (keeps the secret out of `ps`; `-i` does not report failures, so the write is read back and compared byte for byte). `security -i` reads 4095-byte lines and runs a longer one in pieces, the first of which saves a truncated item; the item also holds Claude Code's MCP logins (5.6 KB on the user's Mac), so a payload that does not fit goes as arguments (`ClaudeProvider.keychainWrite`). Renewals and their failures also go to the system log: `log show --predicate 'subsystem == "com.tokenanxiety.app"' --last 1d`. Only one renewal at a time, and a refused refresh token is never retried: reusing a rotated token can sign Claude Code out.
- **Codex**: `codex app-server` over stdio, newline-delimited JSON-RPC without the `jsonrpc` field: `initialize`, `initialized`, `account/read`, `account/rateLimits/read`, `account/usage/read`. Prefer `/Applications/Codex.app/Contents/Resources/codex` (kept up to date by the desktop app). `codex app-server generate-json-schema --out DIR` prints the protocol. Free plans have a monthly window.
- **Antigravity**: its `language_server_macos*` process has `--csrf_token` on its command line; find its ports with `lsof`, POST `GetUserStatus` (Connect JSON, self-signed TLS on 127.0.0.1). Proto JSON omits zero values: no `remainingFraction` means 0 left. Several servers can run; variants like "(Low)/(High)" share one quota.
- **Cursor**: `state.vscdb` (SQLite). With Cursor closed a read-only WAL open fails with SQLITE_CANTOPEN; it is retried with `immutable=1`. Usage: `cursor.com/api/usage-summary` with cookie `WorkosCursorSessionToken=<userId>%3A%3A<accessToken>` (amounts in cents).

- **Claude Code transcripts** (`projects/**/*.jsonl` under `CLAUDE_CONFIG_DIR` and `~/.claude`): every response is an `assistant` line with `message.usage`. One response is written once per content block and again as its output grows (same `message.id` + `requestId`): count it once, keeping the largest figures (on the user's Mac, 47 k lines were 17 k responses). Forked or resumed sessions copy old lines into new files, so the counted keys are kept for good. Subagents live in `<session>/subagents/agent-*.jsonl` with the parent's `sessionId`, `isSidechain` and `agentId`. Titles come from `custom-title` and `agent-name` lines. Claude Code deletes transcripts after `cleanupPeriodDays` (30 by default), which is why the ledger keeps its own history. `<synthetic>` responses are not model calls.
- **Protected folders**: never read files under `~/Documents`, `~/Desktop`, `~/Downloads`, iCloud Drive or `/Volumes` from the app (`ProjectNames.isProtected`). macOS answers with a permission prompt and blocks the read until the user replies; an ad-hoc signed build asks again after every rebuild. Running from Terminal hides this, because the CLI inherits Terminal's access.
- **Codex rollouts** (`$CODEX_HOME/sessions/YYYY/MM/DD/rollout-*.jsonl`, moved to `archived_sessions/`): `token_count` events carry `last_token_usage` (input includes the cached part) and the thread's `total_token_usage`; an event that repeats the total is the same request. Checkpoints are keyed by file name so archiving does not count twice. `parent_thread_id` marks a subagent. The newest `rate_limits` in these files stand in for the quota when the app-server and the HTTP endpoint fail.

## Checking the UI

`screencapture -l <windowID>` renders glass windows blank; capture a screen region with `screencapture -R x,y,w,h` instead (window bounds from `CGWindowListCopyWindowInfo`). The panel closes on any click outside it, so capture right after `--open-panel`. A Settings window opened from the background stays behind the frontmost app; it is not glass, so `-l` captures it.

`ImageRenderer` (the share card) waits on the app's run loop: it hangs under `--print`, which has none. It draws 16 bits per channel with alpha, so the card is flattened to 8-bit sRGB before saving (11 MB → 2.6 MB).

The README's Statistics shots (`docs/stats-*.png`): `--demo --open-stats SECTION -AppleLanguages "(en)" -AppleLocale en_US`, captured with `screencapture -l` (the window is 1080 × 720 by default so the whole toolbar fits in English). The share cards: `--demo --export-card`, scaled to 1200 × 630. Don't relaunch the installed app over and over while testing: each launch asks Anthropic for the quota and a burst gets a 429.

To see a language, launch with `-AppleLanguages "(es)"` (or `(en)`). The README screenshot (`docs/panel-dark.png`): `-AppleLanguages "(en)" -AppleLocale en_US -hiddenInMenuBar "(cursor)" --demo --open-panel` (the argument domain overrides the user's own menu bar choices for that launch only) over `scripts/backdrop.swift dark`, captured from y=0 to the panel's bottom, with the other apps' status items in the strip painted over. macOS 26 takes the menu bar's appearance from the wallpaper, not from light/dark mode: on this Mac the status item stays white in light mode, like the system's own items.
